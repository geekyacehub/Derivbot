# Safety audit — 2026-11-26

This is a source review, not a certification or a complete production security assessment. No real-account trading was tested. **Do not use this app to make trading decisions or operate funded accounts.**

## Production real-data policy

The production interface no longer starts the mock feed, places simulated orders, runs simulated bots or displays fabricated testimonials. Replay, simulation journal, copy trading and placeholder lessons are inaccessible pending verified implementations; test-only simulator code remains in the repository. Account manual trading and verified demo-account automation remain available. This policy is not a guarantee that every displayed detail is correct: tick-grouped charts and calculated signals remain approximations, digit analysis now waits for per-symbol Deriv precision metadata instead of falling back to configured precision, account tracking is incomplete, and Deriv integration has not been verified against the live service.

## Immediate safeguards in this change

- Manual account orders request a correlated Deriv quote and require explicit confirmation; connected order previews no longer show simulated payouts. The manual interface supports tick durations only. A configured maximum-stake percentage is checked before requesting a quote. Experimental auto-trading now supports verified demo accounts after explicit confirmation; real-account bot execution remains unavailable. Disconnected simulation remains available. Unsolicited proposal responses no longer trigger purchases. The manual and demo bot paths track locally confirmed contract IDs and settlement updates, and persist a warning when a buy result is uncertain. It has not been tested against Deriv, is not a complete account-history reconciliation, and does not enforce other risk limits; check contracts in Deriv.
- Connecting stops the simulator bot and is blocked while simulated contracts are open. Mock ticks pause when an account is connected.
- Credential-bearing sync links and follower-token entry are disabled; random indicator values are no longer shown.
- Digit extraction uses the configured symbol precision, strict under-barrier frequencies are corrected, and simulated contracts count ticks per symbol. Manual settlements no longer update bot results.

## Critical findings still requiring remediation

1. **Execution lifecycle and account safety:** manual and demo-bot proposal/buy requests are correlated and locally tracked, with mocked WebSocket lifecycle coverage. Duplicate authorization and cancelled async connection responses are ignored, and OTP socket URLs are constrained to Deriv domains. Corrupt or inaccessible local account tracking now blocks new orders pending explicit verification and acknowledgement; damaged risk settings fail closed. Local recovery does not reconstruct lost history. Account history reconciliation and independent risk limits remain incomplete. Before relying on account trading, build a fully tested state machine with settlement reconciliation and independent limits.
2. **Data provenance:** Simulated and connected ticks are separated. The production UI requests active symbols first, offers active Deriv symbols with initial subscriptions for configured markets and on-demand subscriptions for additional markets, and removes subscriptions that fail; failed discovery blocks account quotes until reconnect. Live history starts empty on connection; digit analysis in production requires Deriv tick precision metadata; if it changes, affected tick history is cleared and a running demo bot for that symbol stops. Raw prices remain visible without precision metadata. Candles are tick-grouped approximations, not time-based API candles. Subscription errors, precision fallback and reconnect behavior still require integration testing against Deriv before using signals.
3. **Credentials:** API tokens remain in memory by default; users may opt in to storing an authorized token in sessionStorage for tab refresh. Scripts and extensions with access to the origin may read it, and browser session restore or tab duplication can preserve or copy it. Explicit disconnect attempts to clear it. Legacy localStorage token and follower entries are removed during initialization where storage permits. OAuth tokens may still arrive in URLs and reach hosting/proxy logs before JavaScript can remove them. A no-referrer policy reduces subsequent URL leakage, and OAuth no longer requests admin scope. Historical sync URLs may contain readable tokens: revoke affected tokens at Deriv. Journal, alert and account-currency rendering now escape untrusted text, and journal CSV export quotes cells and neutralizes formula-like text. This is not a complete authentication or XSS review; scripts and extensions can access in-memory tokens.
4. **Risk controls:** simulated manual/bot orders now check open exposure, daily loss and stake percentage; simulator bots also check consecutive losses and a session timer. Replays include stake-percentage and streak limits, but not daily loss or timer. For manual account orders only the stake percentage is checked. Demo bots check stake percentage, session loss, consecutive-loss and timer limits; those do not cover account-wide or other-device activity. Browser storage, other devices, open positions and network failures mean these limits cannot guarantee protection against loss. Independent account-level enforcement remains necessary.
5. **Strategies and backtests:** MACD crossover, Bollinger squeeze, cold-digit Differs, Over 1/Under 8, parity-streak reversal, a digit-transition ensemble and one-tick momentum now have separate simulated logic. Replay uses strategy-specific contract durations, and the multi-market frequency scanner replays aligned simulated buffers without using future observations. Mock ticks are not a real 1-second feed; frequency rankings ignore contract prices and do not establish an edge. Fibonacci, Oscar-style, Paroli and capped half-Kelly now have shared, tested simulator/replay sizing policies and use the same frequency-scan entry signal. Half-Kelly uses an uncalibrated historical score and fictitious payout assumptions, not a verified advantage or Deriv quote. Some clearly labeled presets still share the same frequency scan; unsupported strategies are marked as not implemented. Builder RSI, recovery and stop blocks are applied in simulation and replay. Replay also offers an independent chronological half-split comparison with separate warm-ups and balances; it is not parameter tuning or a validation of profitability. Neither simulator nor replay reflects Deriv pricing or execution; scores and win rates are not validated probabilities and payouts are illustrative.
6. **Other features and claims:** copy trading is not implemented, academy lessons are placeholders, testimonials are unverified, several indicators are approximations, and AI evaluation now resolves predictions against the next accepted same-symbol tick, expires pending entries on feed changes/reload, and reports per-symbol/source hit rate and Brier score. Legacy entries are excluded from the new metrics; live ordering and feed behavior still require integration testing. Documentation and interface contain additional inflated claims. No profit or performance claim is substantiated.
7. **Testing and operations:** no automated test suite, dependencies lockfile, CI, threat model or monitoring existed in the reviewed revision. Add unit, integration and mocked WebSocket tests, browser tests, static analysis and deployment security headers.

## Suggested next phases

1. Replace misleading labels and placeholders; clearly isolate simulation and remove unsupported account features.
2. Build a deterministic per-symbol data pipeline and realistic contract simulator with documented assumptions.
3. Rewrite each strategy and backtester around the same decision and settlement engine; validate with reproducible fixtures.
4. Design credential handling and a fail-closed order manager, then test against mocked API and a Deriv demo account before considering real-account bot trading.
